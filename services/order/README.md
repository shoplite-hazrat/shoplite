# order-service

Order API for ShopLite. Python 3.14, FastAPI, SQLAlchemy 2 (async) + Alembic, PostgreSQL, NATS JetStream.

## API

| Method | Path | Description |
|---|---|---|
| POST | `/v1/orders` | Place an order `{customerEmail, items: [{productId, quantity}]}` |
| GET | `/v1/orders/:id` | Get one order |
| GET | `/v1/orders?limit=20&offset=0` | List orders, newest first |
| GET | `/healthz` / `/readyz` / `/metrics` | Liveness / readiness (Postgres) / Prometheus |
| GET | `/docs` | OpenAPI UI (generated by FastAPI) |

Errors: `422` invalid input or unknown product, `409` insufficient stock, `503` catalog unavailable (with `retry-after`).

## How an order is placed

```
POST /v1/orders
  1. GET catalog /products/:id for each product   (price + name snapshot)
  2. POST catalog /products/:id/reserve           (idempotent per orderId)
     any failure: POST /release for every attempted product (compensation)
  3. one DB transaction: INSERT order + items + outbox event
  4. 201 Created
background: outbox relay, every 1s
  SELECT unpublished events FOR UPDATE SKIP LOCKED, publish to JetStream
  subject orders.created (Nats-Msg-Id = event id), then mark published
```

- **Saga with compensation.** There is no distributed transaction. Each step has an undo, and reserve/release are idempotent, so retries are safe.
- **Transactional outbox.** The order and its event commit together. NATS being down never loses an event and never fails an order; events wait in the `outbox` table. Watch `outbox_pending_events`.
- **At-least-once delivery.** JetStream dedups on `Nats-Msg-Id` within its window. Consumers must still be idempotent.
- **Known limitation:** if the process crashes between reserving and committing, or a release call fails, stock stays reserved. Production systems run a reconciliation job for this. Failed releases are logged at ERROR.

## Configuration

| Variable | Default | Notes |
|---|---|---|
| `DATABASE_URL` | required | `postgres://user:pass@host:5432/orders` |
| `CATALOG_URL` | `http://catalog:3000` | |
| `NATS_URL` | `nats://nats:4222` | |
| `LOG_LEVEL` | `INFO` | JSON logs to stdout, with `request_id` |
| `DB_POOL_SIZE` | `5` | Per pod |
| `CATALOG_TIMEOUT_SECONDS` / `CATALOG_RETRIES` | `2.0` / `2` | Exponential backoff between retries |
| `OUTBOX_POLL_INTERVAL_SECONDS` / `OUTBOX_BATCH_SIZE` | `1.0` / `100` | |
| `SHUTDOWN_TIMEOUT_SECONDS` | `10` | Keep below `terminationGracePeriodSeconds` |

## Develop

```bash
uv sync
uv run ruff check . && uv run ruff format --check . && uv run pytest
DATABASE_URL=postgres://... uv run alembic upgrade head
DATABASE_URL=postgres://... uv run python -m order_service
uv run alembic revision -m "add column x"   # new migration
```

## Container

```bash
docker build -t shoplite/order:dev .
docker run --rm -e DATABASE_URL=... shoplite/order:dev alembic upgrade head   # migrations (a Job in k8s)
docker run --rm -p 8000:8000 -e DATABASE_URL=... shoplite/order:dev           # API + outbox relay
```
